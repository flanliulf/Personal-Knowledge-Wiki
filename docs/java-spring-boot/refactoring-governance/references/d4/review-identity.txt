## 结论（Decision）

**`D3R-01` 已在设计层闭环。本专项未确认需要追加的 P1/P2 设计问题。** 主文已明确实例身份、版本、去重条件、集合成员、部分覆盖、新版本失效及复用依据。验收附册和机器规格承接相同规则。未发现对象身份修订新增全仓 hash、每行实例、每次全量资格测试或独立报告的要求。

本结论不代表实现 schema、真实对象绑定或证据复用引擎已验证。307 个设计用例仍为 `NOT_RUN`。本专项不对全部子手法资格覆盖作最终裁决；该维度由并行资格评审负责。

### 机器核对结果（Machine Consistency Checks）

新建的 [identity-audit.py](identity-audit.py) 只读取 D4 索引，输出 [identity-audit.json](identity-audit.json)。17 项检查全部通过：

- 全部 307 个索引 ID 唯一，当前规格 revision 均为 D4；133 个治理正文与索引的主体、预期、oracle、supporting 和本轮关系字段一致。
- 全部主对象含 kind/ref/scope，使用六种允许类型；`primary_subject` 与兼容字段 `verdict_subject` 没有冲突。
- supporting verdict 引用可解析且标识唯一；R01 三个符号身份、R03 条件复用、R04 两个实例及 R09 集合映射符合契约。
- 新四个 OC 的 22 个具名变体展开为 26 个独立候选逻辑 ref。`required_candidate_ids` 中的多个错误候选各有自己的对象；未把 variant 集合模板当一个 code_postimage。
- 307 项索引以及新技术变体均为 NOT_RUN；未出现 apply completed 却同时给出 FAIL/NOT_CHECKED 的直接字段冲突。

静态检查不能证明全部保护性质已充分覆盖，也没有执行被设计的选择器或资格 fixture。26 个候选是输入规格中实际列出的独立候选数，不是本轮执行次数。

## 后续实施建议（Implementation Follow-up）

以下是已定契约的实现化建议，不作为本轮新增设计问题，也不要求现在创建文件或测试：

1. 实施 schema 时，以 R01/R02 为中心加入 identity 规范化的参数化检查：只变 ref、只变 revision、已证实 alias、相同内容不同用途、未绑定 identity。保留必要维度，无须新增案例族。
2. R03 绑定真实实现时，分别注入充分与不足的复用依据，确认 q 缺依据时为 NOT_CHECKED；同时保留原执行对象和当前覆盖引用。不能只验证字段存在。
3. 若实现集合汇总，复用 R09/R04 验证成员版本变化导致 manifest 变化；单对象与组合执行不创建空 manifest。
4. 原有复合 case 的 fixture 绑定阶段按其 variant 固定实际身份，继续复用已有 `expected_per_variant`；无需统一改成大量新的 case ID。
