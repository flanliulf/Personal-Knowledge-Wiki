# 聚合设计行为用例（Aggregate Design Behavior Cases）

## 使用说明（Usage）

以下场景均为虚构输入，不代表真实项目事实或授权。它们用于检查本技能能否遵守边界并形成可复核输出。初版所有用例均为 NOT_CHECKED；静态阅读或编写预期结果不是行为测试。

真实执行须有相应授权。记录宿主及版本、Skill 源包 hash、实际输入、预期、实际输出、结论及证据。执行后将记录保存在用户指定的位置，不改本包用例预期来迎合结果。没有相应条件时保留未检查状态。

## 用例（Cases）

### AGG-01：重复技能的并发新增（Concurrent Duplicate Skills）

输入：业务已确认同一员工不能重复拥有相同技能类别。A、B 同时读取空技能集合，均准备新增 Java 技能。已有方案只描述事务包裹两个写入。
预期：复用规则ID，展示读取与提交交错，提出一致性边界和可行机制的候选；仅有事务说明不足以确认安全。实际技术机制未知时追问，保存 needs_clarification。
失败信号：把 @Transactional 当成已证明防重复；将推演报告为生产故障；默认指定数据库隔离级别。
状态：NOT_CHECKED。

### AGG-02：只修改子对象（Child-Only Mutation）

输入：给出一段明确的候选契约：根为 UNCHANGED 时跳过版本检查，随后保存子对象。业务确认子对象修改会影响聚合规则。
预期：指出该入口没有覆盖版本保护。补充“仅改子对象也受根级保护”的设计要求，原子比较旧版本并推进令牌，确认成功判定及同一提交范围；引用输入契约，列出并发验证计划，不直接改代码。
失败信号：只检查根字段修改；读到根版本或检查相等后不推进令牌；声称已完成并发测试。
状态：NOT_CHECKED。

### AGG-03：部分更新缺席字段（Patch Omitted Members）

输入：用户明确 PATCH 只改变技能等级，请求没有工作经验字段。现有分析希望删除所有未列出的经验。
预期：识别缺席字段不应依全量替换示例解释成删除。确认字段缺席、null、空集合的不同含义，交付契约问题与修订建议。
失败信号：自动生成删除SQL；把课程全量更新当通用协议。
状态：NOT_CHECKED。

### AGG-04：跨项目投入比例（Cross-Project Allocation）

输入：业务确认某员工在任何时刻的有效分配总投入不超过100%。模型暂将各项目成员放在各自项目边界，协调方案未知。
预期：明确规则跨越多个项目，追问即时性和可接受失败；比较边界及协调候选，不把所有项目自动合并，不默认最终一致性。
失败信号：只校验某个项目；跨时间相加全部历史；未经业务允许改成延迟检查。
状态：NOT_CHECKED。

### AGG-05：规则即时性未知（Unknown Consistency Requirement）

输入：需求说“库存不能超卖”，没有预留、支付、取消或可补偿窗口定义。
预期：保留 unknown，提出会影响边界的具体问题；可列场景和候选，但不能确认聚合边界或提供确定技术方案。
失败信号：凭常识设定预留协议、锁类型或业务允许的超卖时间。
状态：NOT_CHECKED。

### AGG-06：单实体聚合（Single-Entity Aggregate）

输入：一个审批单具有身份及已确认的状态转换规则，当前范围没有子对象。
预期：评估单实体聚合，记录根、规则和保护入口。没有子对象不构成否决理由。
失败信号：为了构成聚合虚构明细实体；认为所有聚合至少要两个实体。
状态：NOT_CHECKED。

### AGG-07：无法读取实现（Missing Implementation Evidence）

输入：用户问“现有保存逻辑是否已保护所有聚合写入”，但只提供领域模型，没有代码、日志或测试记录。
预期：说明不能判断实现状态，列出需要的保存入口、事务和版本证据；继续交付设计审查问题，不能报告实现通过。
失败信号：根据Repository名称认定实现安全；凭模型给出代码结论。
状态：NOT_CHECKED。

### AGG-08：较大边界与保存失败（Large Boundary and Partial Failure）

输入：候选根包含无数量上限的成员。根版本先更新、成员逐项提交，某成员保存失败会保留之前已提交项。实际数据量和性能未知。
预期：指出原子提交问题，提出受控保存契约；比较边界大小及加载的验证问题，不编造性能数值，不自动拆边界改变即时规则，不生成迁移。
失败信号：忽略已提交部分；凭“最好小聚合”直接改规则；声称已验证性能。
状态：NOT_CHECKED。

## 触发与依赖边界（Trigger and Dependency Boundaries）

AGG-01 用于直接聚合设计请求；AGG-04 也以“帮我分析跨项目分配怎样保持一致”核对同义请求。AGG-05 检查业务输入缺失，AGG-07 检查实现证据缺失。它们的实际触发均未执行。

不应触发输入：“只检查按钮颜色是否符合设计稿，不涉及业务规则。”预期为不启动聚合分析，不虚构根或规则，按宿主既有任务处理。依赖缺失输入：“分析该路径里的聚合实现”，但文件不可读。预期为报告具体缺口，保留可独立的材料分析；核心无法完成则 blocked，不用课程案例代替源码。两项边界探针均为 NOT_CHECKED，真实执行同样需要记录输入、实际输出和证据。
