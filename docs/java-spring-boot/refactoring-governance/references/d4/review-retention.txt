# D4 能力保留与负担评审（Capability Retention and Burden Review）

日期：2026-10-18。范围：本轮独立专项评审；输出仅在临时目录。未修改 D4、历史资料、仓库或实际 Skill。

## 结论（Conclusion）

本专项未确认新增 P1/P2 能力回退，也未确认资格待补被升级为所有任务的新门禁。18 个 `qualification_pending` 保留了相应技术或治理候选。它们暴露的是**相应实现支持声明的资格规格缺口**，不是从设计删除这些能力；同时，不能据“adopted”或父 OP 正反例宣称这些能力已经具备自动执行资格。

D3R-02 在“资格按子手法/变体求闭包、缺口公开、不借父操作通过”的协议层可闭环。这里不把全部 18 分支称为已补齐，也不替代其他专项对 Builder/Factory oracle 与对象身份的一致性判定。

## 剩余建议与验收（Remaining Suggestions and Acceptance）

本专项没有新增 P1/P2。确认一项可减少重复工作的 P3：**OP-15 校验共享资格未引用现成正例。** 操作库252行称缺同语义共享正例，但验收134行的 `CASE-D2-10-B` 已固定两校验单元规则所有者、时点和错误一致，`code_behavior / code_postimage:PASS`，独立 oracle 覆盖成功、各单失败、双失败轨迹与异常消息；`cases.json /cases/24` 与 `/case_index/24` 的 recipe 反向映射仍为空。

真实反例是实施者照待补理由再建同构正例，增加工作；当前主文516/524与OP60允许复用，且pending阻止错误资格PASS，所以不构成P2安全缺口。原则允许复用仍不能替代当前分支的具体映射。最小修订是把B作为 `behavior_preserve` 关联到原分支，派生反向索引，把理由收窄为仍缺边界/owner冲突等拒绝分支；保留pending，不直接把整个validation_unit标成mapped。验收应确认资格选择包含既有B、保留独立oracle和证据层、缺拒绝分支仍报告pending、不新增同构fixture。

以下两项是实施阶段的可选建议，不构成本轮 D4 必须继续扩写的理由。

1. **有限首版支持声明。** 复用已有 `supported_variants` 选定首版范围。若宣称四类合并，优先补 OP-15 四项；若宣称参数对象改写，补 OP-21 拒绝例。验收：声明范围、所需分支、pending 和实际结果一一对应；不通过无限扩大名称来承诺所有模式；单个工程任务仍按本次义务选检查。
2. **摘要分开三种状态。** 从现有数据派生来源裁决、资格映射、运行结果。反例是把“223 adopted”“18 qualification_pending”“4 source pending”合成一个覆盖率；当前正文已经禁止这种推论，但短摘要仍可能省略口径。最小建议是在未来生成摘要时附一句口径，不新增第二套状态字段或门禁。验收：300 主条目与 68 分面不相加；76资格分支/18pending与全部NOT_RUN独立表达。

无需拆出第三个入口，无需新设待补专项，不建议为每个真实任务建立18行追踪表，也不要求本轮追读所有历史support内容。来源覆盖的未验证边界继续保留。后续若要扩大支持声明，再读取相应资料和固定独立 oracle。
