# Workflow Patterns（工作流模式）

## Overview（概述）
以下为可选设计模式，不是官方强制分类；示例路径从实际 Skill 根解析，外部写入按已有用户授权执行。根据业务特征，帮助用户匹配最合适的工作流模式。每种模式有其适用场景和设计要点，选择正确的模式能让 Skill 的执行流程更加清晰高效。

## 1. Sequential Workflow Orchestration（顺序工作流编排）

### Applicability（适用场景）
业务必须严格按特定 1-2-3 步骤执行

### Examples（典型案例）
新客户入职、标准化表单创建、部署流程

### Design（设计要点）
- 使用明确的步骤编号（Step 1、Step 2）
- 指明数据依赖关系（"customer_id from Step 1"）
- 关键节点设置验证等待（"Wait for: payment verification"）
- 提供失败回滚指令

### Workflow Example（流程示例）
```
Step 1：<步骤名称>
    - <具体操作>
    - 生成数据：<本步输出，供后续步骤使用>

Step 2：<步骤名称>
    - 接收数据：<来自 Step 1 的数据>
    - <具体操作>
    - Wait for：<验证条件>（如需要）

Step N：<最终步骤>
    - <整合结果>
    - 完成后返回："完成 <任务描述>"
    - 如果 Step X 失败：<回滚指令>
```

## 2. Multi-MCP Coordination（多 MCP 协调）

### Applicability（适用场景）
工作流跨越多个独立服务或平台

### Examples（典型案例）
设计到开发交接（Figma→Drive→Tapd→Slack）

### Design（设计要点）
- 清晰划分阶段（Phase 1、Phase 2）
- 明确数据在 MCP 间的流转方式
- 上一阶段输出作为下一阶段输入参数
- 集中的错误处理机制

### Workflow Example（流程示例）
```
Phase 1：<阶段名称>（使用 <MCP-A>）
    - <操作>
    - 生成数据：<输出数据>

Phase 2：<阶段名称>（使用 <MCP-B>）
    - 接收数据：<来自 Phase 1 的数据>
    - <操作>
    - 生成数据：<输出数据>

Phase N：<最终阶段>
    - 整合所有阶段成果

错误处理（集中）：
    - Phase X 失败时：<应对方案>
```

## 3. Iterative Refinement（迭代优化）

### Applicability（适用场景）
输出质量可通过多次迭代提升

### Examples（典型案例）
报告生成、代码编写、长文档创建

### Design（设计要点）
- "初稿→质量检查→定点修复→重新验证"循环
- 引入脚本进行客观验证（不依赖 AI 主观判断）
- **必须明确停止条件**（防止无限循环）

### Workflow Example（流程示例）
```
初稿阶段：
    1. <获取数据>
    2. <生成初稿>
    3. 保存到临时文件

质量检查：
    4. 运行验证脚本：`python scripts/<script_name>.py`
    5. 识别问题：缺失章节 / 格式不一致 / 数据错误

优化循环：
    6. 针对每个问题进行定点修复
    7. 重新生成受影响的部分
    8. 重新验证
    9. 重复直到验证脚本不再报错（最多 N 轮）

定稿：
    10. 应用最终格式
    11. 保存最终版本
```

## 4. Context-Aware Tool Selection（上下文感知工具选择）

### Applicability（适用场景）
目标相同但需根据条件选择不同工具

### Examples（典型案例）
智能文件存储、工单路由、格式转换

### Design（设计要点）
- 建立清晰的决策树（条件→工具映射）
- 提供备用/兜底选项（Fallback）
- 向用户解释选择原因（透明度）

### Workflow Example（流程示例）
```
决策判断：
    - 检查 <条件 1>：如果满足 → 使用 <方案 A>
    - 检查 <条件 2>：如果满足 → 使用 <方案 B>
    - 默认/兜底 → 使用 <方案 C>

执行选定方案：
    - 调用对应工具/方法
    - 向用户解释选择原因
```

## 5. Domain-Specific Intelligence（领域专有智能）

### Applicability（适用场景）
需要注入特定领域的专业知识、规则或合规性要求

### Examples（典型案例）
支付合规检查、法务合同审批、医疗数据处理

### Design（设计要点）
- "先合规后行动"原则
- 在执行操作前强制规则检查
- IF/ELSE 条件分支处理合规与不合规情况
- 完整的审计追踪记录

### Workflow Example（流程示例）
```
合规检查（处理前）：
    1. <规则检查 1>
    2. <规则检查 2>
    3. 记录检查决策

执行处理：
    IF 合规通过：执行 <核心操作>
    ELSE：标记为需人工审核，创建 <问题记录>

审计追踪：
    - 记录所有检查结果
    - 生成审计报告
```

## Selection（模式选择）

| 业务特征 | 推荐模式 | 关键标志 |
|:---------|:---------|:---------|
| 必须按固定步骤执行 | 顺序工作流 | 有明确的先后依赖 |
| 涉及多个平台/服务 | 多 MCP 协调 | 数据需要跨平台流转 |
| 输出需要反复打磨 | 迭代优化 | 质量可逐步提升 |
| 相同目标不同实现 | 上下文感知 | 需要条件判断选方案 |
| 有行业规则约束 | 领域专有智能 | 必须先检查再执行 |
| 简单直接 | 不使用复杂模式 | 无复杂依赖或分支 |
