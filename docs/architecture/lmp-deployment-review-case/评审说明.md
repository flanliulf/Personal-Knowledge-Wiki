# LMP 部署架构案例评审说明（LMP Deployment Case Review Notes）

## 范围与状态（Scope and Status）

本轮按用户“先拿 LMP 案例画图，评审通过后再做通用体系”的要求执行。产物为三个可独立评审的单页部署图及其交互预览。核验日期为 2026-10-14。状态为待用户评审。

采用范围包括网络与部署边界、服务节点、协议与目标端口、外部调用方向、入口与短链、样式适配。没有开展客户环境部署、端口探测或 DNS、TLS、SDK 运行验证。既有交付文件保留，本案例位于独立目录。

## 样式适配与差异（Style Adaptation and Differences）

三版使用同一组项目节点和关系。原示例中的 IP、域名、Pod 数量、Ali / Huawei 云环境、额外数据库和网络枢纽没有直接成为项目事实。

| 版本 | 精确继承或测量 | 本案例必要适配 |
| --- | --- | --- |
| 目标 1 | 原图标像素提取；测得的 sRGB Subnet `#E7F1F8`、公共网络 `#FEF6E8`、VPC `#3E871F`；图标采用提取后的实际包围框尺寸。 | 位图缺少原生边界组件，使用目标 3 的同类型原生角标实现，再覆盖测色。Arial 与部分字号是项目配置 / 候选值。展示单环境拓扑，扩容业务区；SaaS 位于云框外，避免推断外部服务云归属。 |
| 目标 2 | `umlFrame`、`#DAE8FC / #6C8EBF`、50 × 48 K8S 图标、12 / 11 号 Helvetica、折角便笺。 | 将示例 DMZ 对应为“公共入口”，不增加项目未提供的独立 DMZ Subnet。新增数据 Subnet，置于同一 VPC。每个 Pod 图标代表一个具名服务节点，不表示副本数量。应用容器扩容；圆角保留可见半径 18，使用 `absoluteArcSize=1;arcSize=36`，并与实际 SVG 的 `rx / ry` 对照，避免随扩容放大。 |
| 目标 3 | `aws4.group` 组件、云框 `#232F3E`、VPC `#248814`、Subnet `#E6F2F8`、锁标与 `grStroke=0`；TKE 34 × 30、Gateway 34 × 34；主字号 14。 | 以外部 SaaS / 客户系统连接区对应右上 / 右下版式。保留一个 VPC，应用分区采用灰框，避免将应用卡片误解为额外 VPC。不添加 Network Hub、专线或其他云。示例 `shape=link` 表达网络连通，本案例应用调用使用有方向的单线箭头。 |

服务图标按具名服务节点解读；集群边界以 K8S 运行区为准，图标数量不代表集群数量。

三版均增加协议标签和必要连线通道。目标 1 的连接标签字号为 18；目标 2 为 11；目标 3 为 14。原 20261012 的“字号 18”保留为该案例样式配置，依据本会话已提出的多样式方案，不自动覆盖其他两种参考的字号。

实线按 LMP 已确认展示口径覆盖参考中的虚线。交叉采用跨线弧，不表示连接。图标名称、协议、端口和调用方向用于项目内容验收；原样参考与项目图的节点数量和坐标不同。**本轮交付是可复核的项目适配样张，未宣称原样逐像素复刻已通过。** 请分别评审样式还原与项目完整性。

## 检查结果与证据（Validation Results and Evidence）

三个源文件分别进行 25 项结构、语义和几何检查；实际图源与 PNG / SVG 哈希绑定于 [导出回执](references/render-receipts.json)。全部连接保持端点引用；节点在对应父框内；连接不穿越图标、名称、边界标题或协议文字。检查细项及结果见 [本轮回执](references/validation.json)。圆角的源码参数与实际显示效果见 [原生样式对照](references/native-style-comparison.json)。

主 Agent 检查了实际导出的全图和局部服务区、数据区及外部区。评审页面的样式切换、100% 缩放、关系高亮、清除高亮和参考图切换经过浏览器检查。核对 1440 × 900、1600 × 1000、1920 × 1080 三种桌面尺寸。页面横向溢出、脚本错误和外部网络请求分别记录在 [浏览器回执](references/browser-validation.json)。图内可缩放与平移，不以隐藏图形替代可读性。

人工审美和还原度尚待用户评审。实际网络、DNS / TLS、SDK / 接入端点、短链公开解析及跳转机制尚未运行验证。图示的 UAT 登记端口与用户确认口径已明确采用，不补造 PROD 实测结果、SaaS URL、302 / TTL 或失效页。源文件静态检查、浏览器行为检查、视觉检查与客户环境运行验证分别报告。

## 建议评审顺序（Suggested Review Order）

1. 先看目标 1，核对 VPC、两个 Subnet、入口、标品边界和共享 PG。
2. 在关系选择器逐条查看 Gateway / Backend、三条直接代理、标品回调与 XXL-JOB 双向职责。
3. 核对企微与客户系统方向、CDP 读取 COS、Taiji 到外部 SaaS 的出网关系。
4. 对照三份原参考，评审边界、图标、字体、连线及信息密度；注明可接受或需要调整的样式适配。
5. 确认案例后，再将经评审规则、素材与检查方法提炼为通用体系。
