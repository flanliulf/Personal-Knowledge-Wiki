# 文档结构指引（Document Types）

## 使用方式（Use）

先判断读者要完成什么，再从下表选取必要内容。此表是检查清单，不是固定模板。已有文档可沿用有效结构；无证据的栏目留待确认，不编造内容填满表格。

| 类型 | 读者的主要问题 | 优先核实的内容 |
| --- | --- | --- |
| `README` | 这是什么、适合谁、怎样开始、到哪里找细节？ | 项目用途、前提、安装或运行命令、最小示例、目录或后续文档链接。 |
| 设计文档 | 为什么这样设计、边界在哪里、会影响什么？ | 目标与非目标、现状与约束、方案、取舍、接口或数据变化、风险、验证方式、未决问题。 |
| 接口说明 | 怎样调用、会返回什么、失败时怎么办？ | 端点或函数签名、鉴权和前提、参数、请求与响应、错误、兼容性、实际示例。 |
| 教程 | 按什么顺序做、怎样知道每步成功？ | 读者前提、环境、准备步骤、操作、预期结果、常见失败与处理、完成后的下一步。 |

## 交付复核（Review）

1. 文档开头能让目标读者判断是否适用。
2. 名称、路径、版本、命令、字段和行为均有来源；示例与真实接口一致。缺少证据时明确标注或询问。
3. 每个必要步骤有前提、动作和可观察结果；读者不需要猜测省略的条件。
4. 技术结论与当前实现状态一致；计划内容没有写成已上线或已验证。
5. 标题、链接和相邻段落能引导读者，不重复同一信息。
