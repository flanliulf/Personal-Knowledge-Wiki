# 操作规则（Operation Rules）

本文是 `SKILL.md` 执行流程中三个入口的详细规则，执行对应入口前读取相应章节。命令写法与参数见 [运行指南](workflow.md)，数据字段见 [数据契约](data-contract.md)。

## 生成提案（Audit）

1. 取得全局执行锁。已有锁则报告正在执行并退出，不排队、不定时重试、不按超时接管。
2. 明确实际来源与覆盖范围；首版改名只支持 Codex。归档目录按实际分页读取，无法读取的范围单独披露。当前工具若仅返回最近若干项，不得称为全量。ChatGPT 等来源记录为不支持，不混入 Codex 执行项。
3. 读取目录、创建时间及必要证据，构造 `work/` 下的临时提案输入。按稳定会话身份去重；对保护字段只记录实际观察到的值，未能核验的字段明确列出，不用 `null` 冒充未知值。
4. 用 `prepare` 校验并保存不可覆盖的 `output/<batch-id>/proposal.json`。保留项也列入 JSON，说明原因；工具不可访问、目录缺失等写入覆盖范围说明。
5. 用 `review` 从同一 JSON 生成可读对照表，表头严格为 `| 原名 |修改后名|`。批次标识、哈希和覆盖信息放在表格外；同名会话按来源/项目分组说明，不能靠标题认领身份。若分段展示，全部获批条目必须展示完成。
6. 释放锁后等待确认，不持锁等待用户。零改名项只报告无需修改，不请求空批次批准。仅生成建议不代表获得写入授权。

## 执行与核验（Apply）

1. 确认用户批准的是已展示的具体批次和提案哈希；在 `work/` 保存真实确认时间及依据。文件哈希不能代替授权。只批准部分或调整新标题时创建独立新批次，不篡改原提案。
2. 重新取得同一全局锁。调用 `start` 将确认依据及提案哈希写入 `execution.json`；已有执行记录的批次不能再次启动。
3. 每条写入前重新读取当前标题、`createdAt`、运行状态和可观察的保护字段。正在运行则调用 `skip`。调用 `before` 检查当前值：原标题相符才返回可执行；已是目标标题则跳过；出现外部修改、缺失身份时间或保护字段变化则跳过并说明。
4. 只有 `before` 返回 `eligible: true` 才可对该 `threadId`、该主机调用专用改名工具。脚本会在请求发出前将该项记录为 `unknown`；若调用没有发生或中断，结果不会被错误写成完成。
5. 不论工具成功、报错还是超时，都尽可能独立回读，再调用 `record` 保存实际观察与工具结果。每条处理后立即保存，不等整批完成。回读已达目标只能证明观察结果，不伪造因果关系。
6. 检测到保护字段差异时停止后续写入，用 `finish` 结束本轮并说明；不要撤销其他会话正常活动，也不要修改内部元数据。未能核验的字段保留为限制，不能宣称全局状态完全不变。
7. 正常结束调用 `finish`，输出已验证、失败、跳过、未执行和未知数量，并说明保护字段核验范围。释放锁。可处理异常同样释放；进程异常终止留下的锁须经人工确认后清理。
8. 不自动重试。已有 `execution.json`、未知结果或遗留锁时先只读核查并交由人工决定；后续如获授权，基于当前状态另建批次，不覆盖旧结果。

## 生成记录（Report）

用户明确要求生成记录文档时，确定批次；多个候选且上下文无法唯一确定时询问。调用 `report` 从两份 JSON 生成 Markdown，提案阶段缺少 `execution.json` 时只生成未执行提案报告。此操作不访问应用、不提炼新标题、不改名、不补造批准或执行证据。生成报告使用同一全局锁防止读取到正在更新的结果，结束即释放。
