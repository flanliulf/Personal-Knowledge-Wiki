## 使用边界与单一规则来源（Usage Boundaries and Single Rule Authority）

规则含义只由主方案的[规则载体](方案.md#d5-rules)、[触达路由](方案.md#d5-routing)、[保护义务](方案.md#d5-obligations)、[抽象决策](方案.md#d5-abstraction)、[文档规范](方案.md#d5-docs)及[验收要求](方案.md#d5-acceptance)定义。本文将这些规则应用到具体变换，不另设相同规则的第二份权威文本。

每次实际选择一个变换 recipe 后，实例化 `operation_instance`：目标及其 preimage、具体子手法与 canonical owner、选用理由、适用前提证据、义务实例引用、计划变换、允许写范围、所选检查与 oracle、回退定位。只读 analyze 记录候选与事实，verify 绑定既有对象和检查，不因查阅 OP 自动创建改写计划或变换记录。父流程已有同一对象和范围的充分记录时直接引用。`oracle` 是提前固定的判定依据，例如既有契约、调用事件序列、输入输出样本或独立实现；不能用改后实现自身输出生成“正确答案”。下文 `OC-XX-P/N` 的 P/N 是可接受/应拒绝或需分流的逻辑分支，不是测试结果。

本文的 `OB-01`—`OB-18` 都是 `obligation_family`（义务族），不直接代表一项运行结果。所有条目共同消费 `OB-01/02/18`：范围、路由、证据血缘；目标声明变化消费 `OB-03`。实例身份、去重、对象版本变化及证据复用统一引用主文的[对象身份契约](方案.md#d5-subject-identity)，本册不另定义一套键。不同不可变对象身份或版本不能因同 scope/profile/stage 合并；血缘相连不等于同一受评对象。检查通过 `covered_instance_refs` 逐实例声明覆盖；一次组合执行可证明多个对象，但不隐去对象责任或计算成多次独立执行。每条列出的其他义务族是最低补充，实际影响可能增加义务。`RT-*` 只是初始路由提示，最终按主方案求全匹配并集和依赖闭包。普通 SQL、DTO、校验和方法整理只触发自身规则；出现重复候选、共享建议或撤销抽象时才追加 `RT-03`。不因文件含 Spring 注解就把纯注释操作升级为运行语义变更。

回退均指撤回本次已识别的变换差异，恢复相应 preimage 或兼容步骤。须先核对期间的外部修改；无法安全分离时停止并报告，不执行仓库级 reset，不覆盖用户改动。每个操作的反向手法也重新评估适用性，不能以“回退”绕过范围和契约。

### 子手法关系与唯一维护位置（Recipe Relations and Canonical Ownership）

`recipe_ref` 使用 `OP ID + subrecipe` 表示，例如 `OP-21/builder`。它是操作族内的定位，不新增用户入口、另一套编号或独立规则副本。每个被选中的子手法解析到一个 canonical owner，再取得其条件与义务；加载同一个 owner 一次即可，不生成重复变换记录。

| 关系 | 含义与加载行为 | 本库示例 |
|---|---|---|
| `alias` | 不维护技术细则；选择该入口即解析到同一 canonical recipe，保留入口理由 | `OP-27/Builder → OP-21/builder`、`OP-27/Factory → OP-23/factory` |
| `requires` | 已选择该 recipe 后，必需消费的已适用规则或协议；可复用现有证据，不代表重跑 | `OP-15/consolidate → 主抽象决策`，`OP-45/optimize → PB-05` |
| `conditional_requires` | 条件成立才加入闭包；条件 unknown 时补相关事实，不把所有关联全部加载 | 声称性能收益→PB-05；多个独立单元需要分批→PB-02；普通证据不足且选择高级策略→PB-06 |
| `informational` | 只用于发现相关候选，不授予写权限，也不自动加入闭包 | OP-45 中与查询/缓存/并发候选有关的其他 OP；仅浏览模式索引 |

### 用例资格与本次检查（Qualification Cases and Task Checks）

[统一验收规格](验收与资格输出.md)区分 `qualification_case_set` 和 `required_check_set`。前者验证将来实现的 recipe、引擎或 adapter 是否覆盖适用的正确与拒绝分支；后者只为当前真实任务选择充分检查。不能每次执行一个 OP 都要求创建或重跑该 OP 全部正反 fixture。也不能因当前任务无需某负例，就在 recipe 实现资格中删除关键拒绝用例。

### 子手法资格清单与支持边界（Recipe Qualification and Support Boundary）

本节消费[主文子手法资格契约](方案.md#d5-recipe-qualification)。技术前提、支持范围及必要分支只在下面的 canonical 操作卡维护；验收索引和 `qualification-spec.json` 是派生视图，不成为另一份权威。路径仍是 `OP/subrecipe`，不新增 Skill、操作族或独立目录。`supported_variants` 表示**拟支持且已限定范围的设计变体**，不代表实现已通过。

每行登记 `canonical_recipe_id`、`supported_variant`、必要分支 `branch_id`、性质、`case_id + variant_id` 与 `coverage_role`。普通旧例使用 `variant_id=base`；新构造例使用卡中具名变体。`mapped_in_design` 仅表示该限定分支已有可判定规格与关系；`qualification_pending` 表示具体分支缺失或证据层不够。所有运行状态仍为 `NOT_RUN`。若一个 recipe 含多变体，按实际声明的变体选择；某变体 pending 不抹掉另一变体已存在的映射，也不允许把后者外推为整个 recipe 已通过。

资格选择先解析 canonical owner，再按声明变体计算必要分支。缺正例、缺关键拒绝例、只关联父 OP、只给 owner 加载例，均不能报告相应技术资格 PASS。`CASE-D3-R07` 只证明 Builder 的别名与直接入口加载相同 owner/前提，不能替代 `OC-21-BP/BN`。OP-27 没有第二套支持范围；从别名进入所得 recipe、变体和分支集合与直接入口相同。alias 只确定 owner：同 owner 有多变体时，须依据入口语义及明确支持声明绑定确切 variant；State 不能退回已映射的 stable_strategy。缺失或歧义保留 qualification_pending，不能猜测或回退到较容易通过的变体。Builder/Factory 的当前单变体仍可直接解析。共享 fixture 可复用一次充分检查，仍须逐对象、逐分支说明覆盖。

登记按需进行：本轮补已发现的 Builder/Factory 和既有 canonical 模式/抽象选择关系，保留现有技术候选。其他 OP 中提到的具名特性、API、具体工具和方向，不因出现在候选文字或父 OP 有正反例就自动获得实现资格。声明支持前只补**被声明的具体变体**；未登记的选择记 `qualification_pending` 并写明该 owner 内的分支缺口，不提前穷举全 Java 生态。已有窄范围用例可直接引用，不能重新命名后扩大其 oracle。

这是一份实现资格边界，不是每次任务的必跑表。纯注释、改名或只选参数对象/CQS，不自动加载 Builder/Factory；真实人工重构也不先补全库 fixture。当前 `required_check_set` 仍只按本次义务实例选充分证据。工具或能力未经确认时按既有 GOV-05 处理相关动作，不全局阻断无关任务。按已定需求有意改变构造协议仍转相应行为迁移，不以本表的 fixture 取代项目契约。

## 已恢复的具体操作（Recovered Concrete Operations）

### OP-01：领域命名与消费者传播（Domain Rename and Consumer Propagation）

- **适用与反例**：名称偏离已确认术语；只做符号名称更正。反射名、Bean 名、序列化名、SPI、外部二进制/API 名称不是普通内部 rename 的自动可写范围。
- **步骤**：确认术语证据和声明绑定 → 找源码及隐式消费者 → 将一个符号及必要引用定义为一个可独立验证/恢复的闭合 `transformation_unit` → 预览完整符号改名 → 更新已授权消费者与文档 → 比较绑定、资源和差异。无可靠符号工具时先确认语言结构，不全库字符串替换。
- **义务与 oracle**：`OB-04/07/14`；引用仍绑定同一职责，重载选择和公开名称契约保持。隐式名称契约由资源登记和实际发现/调用检查证明；搜索零结果只记录已查范围。
- **用例**：`OC-01-P` 私有局部变量改名后，声明引用映射和行为结果相同；`OC-01-N` 改类名但 `META-INF/services` 仍旧名，oracle 为真实发现结果，应拒绝完成。
- **停止、回退与路由**：一个符号及必要引用可用 `single_slice`，复用本条范围、预览和验证，不生成空 pilot/expand；只有多个独立单元同规则转换或需要分批扩大时才采用 PB-02 的 batch 路径。相互依赖的引用组不能拆成失去闭合性的半次改名。存在未知外部消费者则保留兼容或转 `PB-04`；绑定改变撤回此次 rename。`RT-02/07/16`，资源/生成链追加 `RT-15`。

### OP-02：常量与术语统一（Named Constants and Terminology）

- **适用与反例**：同一领域含义的魔法值或含混缩写。相同字面值但不同单位、法律/计费规则或生命周期不共享一个常量。
- **步骤**：记录含义、单位、所有者和消费者 → 选择最小可见范围 → 提取同类型常量或更正名称 → 检查初始化时点及调用绑定。可逆地内联没有语义价值的别名。
- **义务与 oracle**：`OB-04/05/06/07`；数字类型、溢出、精度、字符串内容和初始化副作用保持；公开常量另考虑二进制消费者与发布契约。
- **用例**：`OC-02-P` 私有重试次数常量替代同义字面值，调用序列与边界相同；`OC-02-N` 两个值均为 100 的金额比例和批量上限合并，所有者/单位表证明不同，应保留分离。
- **停止、回退与路由**：业务含义不明不命名猜测；撤回常量及引用差异。`RT-02/07`；新共享候选追加 `RT-03`。

### OP-03：提取与内联方法（Extract and Inline Method）

- **适用与反例**：一段连贯职责可被准确命名，或间接方法没有独立价值。行数阈值、需要段落注释或单调用者不构成必做理由。
- **步骤**：列自由变量、读取/写回、别名、返回/早退、异常与资源范围 → 确定参数和返回责任 → 提取一个最小块或将方法体放回合法调用点 → 同步 Javadoc/段落 → 检查所有分支。先比较仅分段能否解决理解问题。
- **义务与 oracle**：`OB-05/06/12/13`；求值次数、顺序、异常位置、锁/资源范围和测试 seam 不变。存在代理、缓存、权限边界时追加 `OB-09/10/11`，不得把普通提取当作纯语法移动。
- **用例**：`OC-03-P` 纯金额计算段提取后，各边界输入结果相同且只有原次数求值；`OC-03-N` 将事务方法内联到绕过代理的调用方，真实事务记录变化，应拒绝普通内联。
- **停止、回退与路由**：无法解释早退或写回责任时拆小或保留；撤回方法及对应调用。`RT-02/01`，涉及抽象边界加 `RT-03`，Spring 加 `RT-08`。

### OP-04：变量、查询与计算时点（Variables, Queries and Evaluation Time）

- **适用与反例**：表达式含义不清，临时变量复用困难，或查询方法使稳定计算更清楚。非纯 getter、当前时间、随机值、可变状态和外部查询不自动等价。

- **适用与反例**：读写责任混杂但可在同一契约边界内部解耦；创建逻辑有稳定变化点。原“取值并原子更新”不能拆成外部两次调用而改变原子性。

- **用例**：`OC-23-P` 公开扣减接口保持原事务，内部提取只读校验与写入步骤，结果/锁序不变；`OC-23-N` 用独立 query+decrement 替代原子扣减，竞争 fixture 超卖，应拒绝。
